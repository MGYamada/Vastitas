# Vastitas contributor guidance

## Scope and sources of truth

- Develop the `.vast` compiler. The implemented milestone is Stage 1b plus path packages, call-only module imports, the initial four-key Nat/Int promotion increment, finite abstract scalar selectors/contracts, scoped edit assemblies, nested edit reborrowing and permanent edit-authority transfer. The `stdlib/src/geometry` package supplies finite affine declarations in sibling `scheme` and `smooth` modules; `stdlib` re-exports them as `std::geometry` alongside canonical arithmetic through protocol 7. Its explicit `geometry_compat` export maps legacy syntax to independently resolved and validated declaration IDs; preserve owners and nominal identities across both syntaxes. Protocol 8 adds the initial static package resource profile, pure return blocks, local nominal numerical values, dependent numerical inputs with static dimension contracts and typed real/complex GEMM. Keep full source/native equivalence, dynamic storage/value flow, general linear algebra, tensor, AD, solver, and physics features separate from implemented functionality. Track the historical Stage 1 completion in docs/stage1-completion.md. Do not add a REPL, user-facing interpreter, LSP, or package manager unless the user expands the scope.
- Read [docs/design.md](docs/design.md) for the design index and the preserved v0.3 proposal. Its pseudocode and conditional mathematical arguments are not claims of implementation or completed formal verification. Use the README and current tests for implementation status.
- Keep documentation honest about what is implemented, tested, proved, assumed, or deferred. User instructions determine the task scope; ordinary authorized work does not require an additional approval ceremony.
- Treat **Fast like C** as the primary performance and architecture goal. Follow [docs/storage-ownership.md](docs/storage-ownership.md): explicit layouts and alias evidence, destination/scratch reuse, visible allocation/packing/retention costs, and equivalent-C measurements. Preserve mathematical meaning and resource safety; do not claim the goal achieved from native compilation or BLAS use alone. Record unresolved performance gaps in the completion gate.
- Use [docs/stage1a.md](docs/stage1a.md) for dispatch, [docs/stage1b.md](docs/stage1b.md) for functions, and [docs/verification.md](docs/verification.md) for theorem statements and proof boundaries. Stage 1b is not completion of the full historical Stage 1 proposal.

## Architecture and semantic boundaries

- Keep canonical stdlib/package module directories aligned with their logical namespace hierarchy, using a directory per module and `mod.vast` as its entrypoint (for example `stdlib/src/geometry/scheme/mod.vast`). Preserve logical declaration identity during layout changes; existing flat/inline language support and arithmetic compatibility inputs remain supported.
- Put the Rust frontend and CLI in `src/`. Send the versioned IR defined in [docs/protocol.md](docs/protocol.md) to Lean; Rust acceptance alone is not semantic acceptance. Update both protocol implementations and relevant tests together.
- Keep `lean-kernel/` independent of mathlib and `lean/`. It owns independent IR validation, checked code generation, and the minimal runtime. Generated programs use the runtime, not the compiler driver or proof oracle.
- Protocols 2–6 retain their wire decoders, then `Indexed.LegacySource` converts unresolved syntax and original namespace/authority metadata into the same `Indexed.AuthoritySource` checker used by protocol 7. The closed adapter-owned compatibility package is ordinary unresolved source and must pass the common declaration/profile audits. Validate the original namespace before injecting it; it must not satisfy a forged source dependency. Native generation uses the exact returned checked Core, `IndexedCodegen` and `IndexedRuntime`. Keep retained `LegacyIndexed`/legacy evaluation theorems separate from this source path and from unproved full source operational equivalence; see `docs/indexed-declarations.md`.
- `IndexedSemantics` is internal bounded semantic test infrastructure. Primitive typing/world-extension, primitive runtime erasure and package payload/opening theorems are connected to real primitive/package/Core checks. `IndexedEvaluationSafety` proves finite typed evaluation for every Core constructor under explicit semantic callee contracts; `IndexedFunctionSafety` derives activation freshness and return-scope preservation from an actual checked function. `IndexedArgumentSafety` transports actual dependent arguments and `IndexedProgramSafety` discharges all callee contracts using the checked dependency order. Keep protocol 2–7 audit/executable totality corollaries tied to the exact returned Core. Finite primitive result compatibility is proved in `GeometryResults`; full source operational correspondence and native refinement remain unproved. Keep these claims distinct; see docs/geometry-migration.md.
- `IndexedSourceChecker.checkDeclarations` accepts internal unresolved declarations through the actual namespace and Core declaration audits. It reconstructs owners from enclosing packages/modules and rechecks reference provenance. It does not check bodies, scalar dispatch or edit assemblies; public protocol 7 composes those checks through `Indexed.Wire.check`; never expose declaration acceptance alone.
- `IndexedSourceTypes.checkDataType` elaborates annotations against that exact declaration certificate and supplied Core bindings, preserving nominal indices and checking scope. It does not prove execution/freshness of arbitrary contexts or replace actual body checking. Keep protocol 7 connected to the actual function, finite-dispatch and authority composition.
- `Indexed.Source.Bodies.checkProgram` is an internal data-function adapter. Preserve its exact reconstruction/returned-Core connection, source ID coverage, all-body typing, and independently resolved call/declaration provenance. It rejects unsupported old bodies and dispatch/edit envelopes; public protocol 7 must use the full authority/Fn/dispatch composition, not this narrower adapter.
- `Indexed.FunctionSource.Compiler.checkProgram` extends the internal AST with independent scalar/Fn lambdas and static specialization. Keep signature-probe and executable states separate, audit every original/lifted body, preserve source identity/coverage and exact target signatures, and independently check both resulting Core modules. Type-index names participate in capture checks. Its accepted Core has typed total evaluation through `IndexedProgramSafety`; source-specialization correspondence and native refinement are separate; public protocol 7 connects Rust/kernel parsing and serialization through the combined entry.
- `Indexed.DispatchSource.checkProgram` composes rich indexed method bodies with the actual finite scalar checker, namespace/membership authority and abstract contracts. Expand and audit every applicable method/key, including nonwinners and out-of-domain keys; infer call keys independently of expected results. Keep exact method/header and target/key/Core correspondence. Its plain dispatch entry rejects edit/authority envelopes; the public protocol-7 entry uses the separate authority composition below.
- `Indexed.AuthoritySource.checkProgram` composes those rich bodies with the actual protocol-6 authority assembler and its final families/footprints. Keep canonical function ownership distinct from each contributor's lexical body scope. Reconstruct applied and unapplied source bodies by canonical contribution ID and original position, audit every specialization/lambda, and independently reject unapplied definitions or their lambdas in executable origins/static targets. Preserve the actual assembly, source mapping and both returned-Core equations.
- The public wire protocols are version 2 for existing flat source inputs, version 3 for existing packages, version 4 (explicit flat/package input) for abstract declarations, package-only version 5 for explicit grants/contributions/assemblies, package-only version 6 for delegated edit loans and permanent authority transfer, and package-only version 7 for unresolved indexed declarations and rich bodies. Version 7 is checked by `Indexed.Wire.check` and its exact returned Core reaches `IndexedCodegen`; preserve the decoder/checker equations and reject forged metadata. Protocol-7 legacy geometry syntax requires exactly one explicit, independently validated library compatibility export; ambiguous exports do not prevent qualified new syntax. The finite migration acceptance and remaining proof boundaries are mapped in `docs/geometry-migration.md`; see `docs/indexed-source.md` for syntax. In all public protocols, the common function compiler lowers static Fn values and invocation to independently audited indexed Core; retained internal Core formats are not alternative wire protocols. Keep actual checker composition connected to the proof oracle when changing this boundary.
- In protocol 6, keep definition identity separate from current edit authority, require explicit delegable grants and exact-module delegation with region containment, suspend parent editing, and return loans inside out. Transfer requires a declaration by the current owner and no active loans. Preserve methods, grants, history and Open obligations; transferred authority does not include abstract membership or contract edits. See docs/edit-authority.md.
- Keep protocol-3 package identity, logical module owners, visibility, imports and unresolved paths in the IR. Lean independently resolves and audits them. Ordinary methods require the exact defining module. Protocol 5 permits external contributions only through an exact owner grant and active exclusive loan; children/imports/public exposure grant no edit authority. Audit complete contribution provenance and final winning footprints, check all applied and unapplied bodies, and require returned loans and completed assemblies. See [docs/edit-borrowing.md](docs/edit-borrowing.md). All manifests and module files are protected inputs. Preserve v2 and `--lib` compatibility; see [docs/packages.md](docs/packages.md).
- Use `Fn<Input, Output>` for function types and `fn(x: Int) -> Int { ... }` for lambda expressions. Lambdas cannot capture outer bindings. Fn signatures contain only scalars and recursive Fn types; generic families are not values or function-valued dispatch keys. Keep the independent capture/static-signature audits, the 4096-specialization limit, and reject differing function targets across branches without constant folding. Audit unused higher-order bodies using separate signature probes; never reuse probes in executable specialization.
- Dispatch uses only Nat/Int/Bool/Unit keys, finite nominal abstract selectors (at most 64 including the six builtins), and Lean-established HasEq/HasOrder facts. Abstract selectors are not value types. Only their exact defining module may add scalar memberships; preserve builtin subtype relations. Check ambiguity over the entire key space, coverage over the union of the concrete generic domain and expanded abstract contract domains, and every applicable specialized body, including nonwinners. Preserve the 4096-key bound and the nominal/capability product order; do not replace it with current inhabitant-set containment or expected-result-type selection.
- Abstract methods are bodyless contracts, never dispatch candidates. Each explicit domain clause must expand nonempty; `domain;` is the intentional empty contract. Each expanded key must satisfy the contract selectors/capabilities and the unique concrete winner must have the exact scalar/Pair result type. Overlapping contracts must all hold. Only the generic's exact defining module may add contracts. See [docs/abstract-types.md](docs/abstract-types.md).
- Keep `lean/` proof-only and independent of mathlib, including transitive packages. Its only Lake dependency is the actual local `lean-kernel/`; import those definitions instead of copying a second model of the implementation. Reuse Lean core proofs and keep mathematical contracts aligned with the pinned mathlib reference as specified by ADR 0001 and #278/#285. Do not use `sorry`, `admit`, or custom unproved axioms to present an obligation as proved. State the scope and assumptions of each theorem; checker proofs do not establish the entire native toolchain's correctness.
- `Graph` is an internal finite crossing-word checker, with profile-indexed authority, ordered nominal ports, explicit signs, and exact returned-graph certificates. Preserve its independent audits and the distinction between conditional interpretation theorems and pending categorical laws/method realization. `GraphRegression` uses an explicit synthetic law predicate; never expose it as production authority. Public tensor resolution and the bridge to actual `Indexed.Core` terms remain pending; see `docs/graph-crossings.md`.
- `Storage` is an internal closed-plan resource checker, separate from pure Core. Preserve allocation provenance, monotone reborrow permissions, suspended parents, inside-out returns, byte-region initialization, both-branch joins and bounded metadata. `StorageCodegen` rechecks the exact original schedule and every native instruction before generation. `lean-kernel/native/` is an optional compiler/oracle/mathlib/BLAS-free runtime; its physical preflight and cleanup tests do not establish source authority or native refinement. Keep it outside the proof oracle. Its Rust/Lean component schema is not public protocol 8; see `docs/storage-ir.md`.
- `StorageFunctions` adds internal affine calls, owned arguments/results and call-scoped borrowed parameters. Keep all-body synthetic probes separate from actual executable expansion; recheck every real caller's layout, initialization and aliases. Preserve exact call-slice replay, restored caller loans, no escaped local owners and final closed-plan acceptance. Static component IDs do not confer namespace authority. The initial public static source composition is separate; dynamic shape/scalar flow and general generative numerical result packages remain pending; see `docs/storage-functions.md`.
- Package-only protocol 8 uses `ResourceProtocol`/`ResourceSource` to reconstruct resource headers, canonical owners, local bindings and calls in the same namespace as the actual full `Indexed.AuthoritySource` checker. Preserve all ordinary/nonwinner/unapplied bodies, separate resource probes, exact source-to-schedule mapping and independently audited pure return fragments. `ResourceCodegen` checks both returned components and the source main’s pure result target; resource headers are never fabricated pure bodies. `value` blocks remain pure and independent of resource handles; static resource dimensions/branches and terminal pure return flow are the initial profile, not general dynamic numerical composition. Link the optional native runtime only when the checked entry needs it. See `docs/resource-source.md`.
- `lean-kernel/numerical` is an optional GEMM adapter and Lean FFI package using pinned sequential LP64 OpenBLAS 0.3.34. `Storage.Action.gemm` independently checks logical access/initialization/separation and exact native lowering; the C adapter rechecks actual arena layouts, aliases, version/ABI and zero-size behavior before writes. Neither grants nominal endpoint/basis/metric authority on its own; public source GEMM must pass the separate `StorageNumerical` composition. Explicit alpha/beta may use machine literals or live initialized one-element coefficient loans. Preserve scalar matching, output separation, actual runtime reads, overwrite’s absent-beta rule, accumulate initialization even for beta zero, and exact coefficient lowering. Keep the documented zero-inner numerical convention separate from field laws. Keep numerical flags explicit and the normal compiler/storage runtime independent of OpenBLAS; see `docs/numerical-adapter.md`.
- Protocol 8 numerical declaration profiles use the actual common indexed declaration checker. Preserve ideal real/complex coefficient coherence, explicit nominal scalar-base objects, independent path provenance and the distinction between smooth real bases and complex coefficients. Old wire versions and old affine primitive/family contracts must reject numerical profiles. These metadata declarations alone do not authorize public GEMM, exact float field laws or native refinement; see `docs/numerical-declarations.md`.
- `StorageNumerical` adds local spaces/bases and typed map views to actual resource-function expansion through public protocol-8 numerical statements. Preserve fresh activation identities, exact nominal endpoints and bases, complete live-loan/layout snapshots, and the certificate linking the product to its emitted resource GEMM. The full public checker independently resolves profile paths and supplies its exact accepted declaration environment; audit receipt origins and link the optional numerical runtime only when the checked entry needs it. Numerical inputs preserve caller identities and create scoped child map loans under explicit static profile/dimension contracts. Keep header dependency/provenance checks, original-caller snapshot validation, actual sibling alias checks and input binding receipts. Initialized owned maps transfer exact input-dependent endpoints/bases, allocation and layout through constructors, inputs, moves and results. Preserve actual result contracts, original-caller checks, no outstanding loans, actual-layout borrowing and allocation-free metadata erasure. Typed dual/conjugate spaces retain their nominal origins and corresponding bases. Canonical involutions and coordinate Hermitian forms are explicit; direct adjoints require exact identity Gram data in the used bases, not tolerance evidence. Transformed maps carry actual read child loans, suspended parents, inside-out release and preserved conjugation through dependent calls. Audit transform receipt origins and exact native flags; never infer dual/metric authority from dimensions or raw layouts. Vector evaluation retains actual corresponding dual/conjugate bases, explicit identity Gram forms and vector interpretation through dependent calls. Preserve the exact child-borrow/GEMM/release schedule, restored inputs and initialized scalar output; do not insert conjugation or reinterpret a conjugate space as a dual. The bounded `OwnedMapTo` package hides one primal target and direct basis while preserving its caller-dependent source basis. Preserve affine opacity, name/owner equality, fresh consuming unpack, actual post-body result certificates, and package receipt origins on both branches. Raw borrowing or erasure must not expose opaque storage. General generative numerical packages, dynamic shape/scalar interfaces, general metric realization and general networks remain pending. These structural certificates do not prove float laws or native refinement; see `docs/numerical-values.md`, `docs/linear-transforms.md`, `docs/vector-evaluation.md` and `docs/owned-map-packages.md`.
- `TensorNetwork` supplies the finite public two-map network profile. Preserve occurrence-local port identity, exact single-use coverage, input-dual/output-vector edge roles, nominal spaces/bases and ordered boundaries. Distinct occurrences may share an immutable map; ports never grant storage ownership. Reuse `StorageNumerical.checkProduct` and the common exact GEMM emitter. Retain graph acceptance, declaration origins and emitted-transition receipts; do not infer conjugation, metrics, dual identifications, trace/copy or order search. Keep general tensor/category/native refinement obligations separate; see `docs/finite-networks.md`.
- `TensorNumerical` supplies a finite rank-three/rank-two coordinate contraction and explicit caller-destination `pack3`. Preserve actual ordered axis bases and corresponding dual origins, exact permutation/grouping byte maps, rectangular loan snapshots, explicit write-release/read-reborrow, output separation and all constructor/packing/contraction receipts. Never manufacture product bases from dimensions or treat factor ports as disjoint storage. Packing adds no internal allocation or conjugation; the fixed contraction emits one checked GEMM. Coordinate-reference proofs are separate from native refinement, tensor-category laws and measured C performance; see `docs/tensor-packing.md`.
- Cached tensor packing records both actual post-pack allocation versions and nominal axis/grouping evidence. Preserve replayed capture/require/forget, fresh dependency names, write/drop/join invalidation, lexical cleanup, ordinary snapshot semantics and allocation-free native erasure. Raw dependency capture grants no nominal packing assertion or memory access; versions do not retain old data. Keep AD/residual retention and general pooling separate; see `docs/cached-packing.md`.
- Preserve the distinction between `Scheme` and `CInfScheme`, explicit geometric bases, and nominal object identities. Equal dimensions or equal descriptors do not identify endpoints. A coefficient-ring marker such as `QQ` is not itself the geometric test object in `Point<X, S>`.
- Preserve point/morphism endpoints through dependent arguments and packaging. Unpacking introduces scoped identities; reject escaping points or mismatched objects rather than erasing the failed check. Only checked IR may reach code generation.
- Preserve the shadowing ban, generative object IDs, arbitrary-precision integers, saturating Nat subtraction, explicit Nat-to-Int conversion, and recursion rejection after specialization. Legacy source libraries remain explicit `--lib` inputs; packages require explicit `--manifest-path` and local path dependencies.
- Homogeneous `Pair<Nat>` / `Pair<Int>` values use independent operand inference and checked constructor/projection operations. Keep Pair out of dispatch keys and recursive Fn contracts; it is not general parametric or dependent data.
- Keep stdlib promotion's value policy separate from compiler typing. Preserve the actual-source IR fixture, checked-body numerical proofs and mutation regressions described in [docs/promotion.md](docs/promotion.md). `VastitasPromotion` is a test/proof library, not a compiler/runtime dependency.
- Keep both Lean projects on the same pinned toolchain and keep dependency lockfiles. Ordinary compilation and generated executables must remain usable without mathlib.

## Validation

- Run checks appropriate to the changed subsystem. Rust changes: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test`. Kernel changes: `lake -d lean-kernel build`. Oracle changes: `lake -d lean build`.
- For changes crossing the compiler boundary, build the kernel before integration tests and exercise both `vastitas check` and `vastitas build` on relevant `.vast` examples. Execute generated binaries and test invalid source or tampered IR when affected.
- For kernel checking, dispatch, function or authority changes, also run `bash scripts/check_kernel_regressions.sh` (the eight existing targets plus `VastitasKernel.AuthorityRegression` and the indexed declaration/package/primitive/Core/legacy-adapter/semantic/wire regression targets). These targets exercise forged checked IR, the actual finite engine (including multiple inheritance and triple intersections), function acceptance/static-signature audits, and nested edit/transfer provenance. Indexed Core/codegen changes also require `bash scripts/check_indexed_native.sh`.
- Preserve the test that the normal compiler path works without mathlib. Add meaningful semantic or regression cases; avoid tests that merely repeat the implementation.
- Storage lowering/native changes also require `bash scripts/check_storage_native.sh`: sanitizer checks, exact generated IR execution, failure cleanup and allocation/copy counters on the optional runtime.
- Numerical adapter changes also require `python3 scripts/check_gemm_native.py --prefix <pinned-openblas-prefix>`; Linux numerical CI runs its `--valgrind` mode with an explicit supported CPU target. Report native tests separately from checker proofs and performance evidence.
- Checked GEMM/lowering/FFI changes also require `python3 scripts/check_gemm_checked.py --prefix <pinned-openblas-prefix>` for exact internal schedules, generated real/complex products, T/C distinctions and failure cleanup. Public mathematical/source acceptance remains a separate requirement.
- Report actual commands and results. If a dependency or toolchain prevents a check, describe that specific limitation instead of claiming the check passed.
