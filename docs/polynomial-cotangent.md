# Exact polynomial cotangent composition

This is the first **mathematical proof slice** of [#361](https://github.com/MGYamada/Vastitas/issues/361),
within the polynomial starting fragment of [CF / #192](https://github.com/MGYamada/Vastitas/issues/192).
It proves a canonical differential and its typed reverse composition for two-variable
rational polynomial presentations at rational points. **It does not prove compiled
AD or constitutional CF.** No Domain Checker or public source feature is added.

## Mathematical objects and direction

The implementation is [PolynomialCotangent.lean](../lean/VastitasOracle/PolynomialCotangent.lean),
in the proof-only Oracle. The separate `VastitasMath`/`VastitasBridge` packages proposed
by #285 do not yet exist; this change preserves the current closed Lake dependency
graph. It reuses `Coordinates.RationalCoordinates`, Lean core `Rat`, and the same
kernel-checked core algebra tactics already used by `StorageMetricLaws`.

The base is fixed to **Q**, with two ordered coordinates and their dual basis.
There is no implicit change of scalar field, metric, conjugation or basis.

| Lean object | Mathematical meaning |
| --- | --- |
| `Plane` | A nominally named affine plane over Q, in the fixed coordinate presentation |
| `Point X` | A Q-valued point of X; not an identification of the scheme with its rational points |
| `Polynomial` | Expressions generated by rational constants, two variables, addition and multiplication; negation and natural powers are expressible |
| `Polynomial.Equivalent` | Explicit congruence generated by the commutative Q-algebra relations |
| `PolynomialMap X Y` | Two coordinate polynomials for a map X → Y |
| `g.comp f` | g after f; substitution of f's coordinates into g's coordinates |
| `Cotangent x` | The coordinate fiber Q dx ⊕ Q dy at the **particular** `x : Point X` |
| `differential p x` | The two formal partial derivatives of p, evaluated at x |
| `pullback f x` | `Cotangent (f.applyPoint x) → Cotangent x`, namely `J_f(x)ᵀ` |

`Point` and `Cotangent` are indexed structures, not abbreviations that forget
their indices. Equal dimensions or equal coordinate arrays do not identify
different named planes. `Cotangent.transport` requires an actual equality of
points of the same plane. Names in this mathematical model are not production
owner, environment, provenance or accepted-Core certificates.

For X →ᶠ Y →ᵍ Z, `PolynomialMap.at_comp` first proves

```text
(g.comp f).applyPoint x = g.applyPoint (f.applyPoint x).
```

The main theorem, `pullback_comp`, then has the explicitly typed statement

```text
seed : Cotangent ((g.comp f).applyPoint x)

pullback (g.comp f) x seed
  = pullback f x
      (pullback g (f.applyPoint x)
        (seed.transport (PolynomialMap.at_comp g f x))).
```

This transport is equality of evaluated polynomial points. It is **not** the
unconstructed sheaf pullback-associativity isomorphism of the general C∞ theorem.

## What the official Lean kernel proves

- `eval_substitute` and `derivative_substitute`: evaluation and the chain rule
  for **every** expression in this two-variable fragment, by structural induction.
- `DerivationAt.coordinates`, `directional_generator`, and `DerivationAt.unique`:
  a derivation into Q with the evaluation-module action is uniquely determined
  by its two generator values, and every pair of values gives such a derivation.
- `equivalent_jet`: both the primal value and every partial derivative respect
  the explicit polynomial-ring presentation relations, including distributivity,
  additive inverses and rational constant arithmetic. Expanded/factored syntax
  does not change the differential under this relation.
- `differential_substitute`: differentiating a substituted polynomial equals
  pulling back its differential. The construction is tied to the canonical
  polynomial differential, not just an arbitrary operation satisfying functor laws.
- `pullback_add`, `pullback_scale`, `pullback_identity`, `pullback_comp`: rational
  linearity, identity and typed reversed composition, with no metric premise.

The proof uses a polynomial presentation and evaluation-module derivations.
It does **not** construct the global module of Kähler differentials, prove its
universal property for arbitrary target modules, or supply a Mathlib equivalence.
Those are separate strengthening/Bridge obligations. ADR 0001 §9's pinned
Mathlib reference (`56a005855ea17e0b0958f73ec801ae140b0a1679`) is unchanged.

`VerifiedRule f` bundles a proposed function with a proof of equality to the
canonical pullback for **all** rational points and seeds. A function with the
right shape is insufficient; the zero rule for identity cannot have this proof.
This is a mathematical evidence interface, not production custom-rule registration.

## Regressions and independent reference reuse

[check_polynomial_cotangent.lean](../scripts/check_polynomial_cotangent.lean) runs
in the existing official Lean proof CI job. Concrete arithmetic uses
`decide +kernel`; no native reflection, `sorry`, `admit` or added axiom is used.

| Case | Expected result |
| --- | --- |
| Identity, arbitrary point/seed | The same cotangent |
| f(x,y)=(x+y,y), g(x,y)=(x,x+y), origin, seed (1,0) | Composite and f* after g* give (1,1) |
| Reversed pullbacks of those same pointed endomorphisms | (2,1), proved unequal to (1,1); both orders have exactly the same type |
| f(x,y)=(x²+y,xy), g(u,v)=(u+v²,uv), x=(2,3), seed (3,5) | Intermediate (7,6), output (43,42), cotangent (345,175) |
| f(x,y)=(x²/2,y), x=(2/3,3/4), seed (3/2,−1/3) | Cotangent (1,−1/3) |
| Wrong middle endpoint, foreign target with identical coordinates, or seed at (2,3) instead of (7,6) | Fails to elaborate at this Lean API |
| Bare custom-rule function or forged zero derivative for identity | Missing evidence fails to typecheck; a certificate for the zero rule is proved impossible |

`fail_if_success` makes the negative elaboration tests fail if an attempted
construction starts typechecking. These are **mathematical API type tests**,
not assertions about the production Fiber/Basepoint checker. The noncommuting
counterexample tests the semantic order error separately from endpoint rejection.

[test_polynomial_cotangent.py](../scripts/test_polynomial_cotangent.py) checks the
same exact witnesses using the existing sparse `Poly` implementation through
`metric_free_reference.py`; it introduces no replacement Python polynomial engine.
Python models rational-coefficient polynomials with real-plane semantics, whereas
this Lean theorem admits rational points only. The shared rational witnesses
agree; there is no theorem identifying the Python evaluator with the Lean one.
Reference tests are independent numerical evidence, not proof authority.

## Remaining obligations

| Boundary | Status after this change |
| --- | --- |
| Two-variable polynomial mathematical fiber law over Q | Kernel-proved as specified above |
| Global Kähler module and pinned-Mathlib correspondence | Not constructed here |
| General C∞ operations and universal C∞ derivations | Pending; ordinary underlying-ring Kähler differentials do not substitute for #261's smooth chain rules |
| C∞-affine admission, smoothness/domain evidence, real/complex scalar extensions | Pending; branches, kinks and selected backward policies are outside this grammar |
| Sheaves, restrictions, effective gluing and pullback comparison isomorphisms | Pending; no atlas/gluing theorem is claimed |
| Actual source/accepted-Core denotation, AD lowering and translation validation | Pending; no theorem about the actual returned Core follows from this model |
| Proof erasure and pass preservation | Pending for AD; removing indices must preserve the same mathematical subject and action |
| Float, storage, native/FFI/BLAS refinement | Pending; exact rational equality does not establish approximate or machine execution correctness |

The existing **8+1 checker architecture** and official Lean-kernel-only proof
authority are unchanged. Neither this proof nor Python success grants compiler
acceptance, native refinement, or completion of CF.

## Reproduction

With the repository's pinned Lean 4.35.0:

```sh
lake -d lean build
lake -d lean env lean scripts/check_polynomial_cotangent.lean
lake -d lean env lean scripts/audit_axioms.lean
python3 scripts/check_boundaries.py
python3 -m unittest discover -s scripts -p 'test_polynomial_cotangent.py' -v
```

The root `VastitasOracle` imports the mathematical module, so the existing
transitive axiom audit covers its definitions and proofs under the unchanged
`propext`, `Classical.choice`, `Quot.sound` allowlist. Mathlib remains absent
from the compiler and Oracle dependencies.
