# Historical Stage 1: finite numerical and storage acceptance map

Acceptance map, 2026-11-01 JST. This records the initial finite contracts and their evidence; it does not close broader parent issues, declare historical Stage 1 complete, or attribute earlier measurements to the current compiler. See the [completion gate](stage1-completion.md) for remaining acceptance work.

The initial finite mathematical/resource functionality has implementation, rejection tests, actual-checker certificates and native execution evidence. The runtime-shape and production IO-result changes are integrated in merged revision `95b848b072712eeee3e2027e0dee275678a3baee`, with the validation recorded below. This mapping publishes that finite-profile evidence; **Fast like C** acceptance and the eventual completion record remain unresolved. Shared-host timings and selected allocation counters do not satisfy the latter.

## #66 — initial linear-algebra interface

The adopted finite interface uses declared numerical profiles and explicit local `space`, `basis`, `map`, `tensor`, graph and resource operations. It is not a claim that a general `std::linalg` module or the proposed `LinearAffine` pseudocode spelling exists. The reviewable contract is in the documents and examples indexed above; naming and wider library packaging remain parent design scope.

| Initial condition, in issue order | Disposition and concrete evidence |
| --- | --- |
| 1. Separate linear objects, tensor values, maps and numerical representations | **Covered for the finite public interface.** N/G retain nominal spaces and ordered bases separately from buffer loans, layouts and representation. Explicit constructors do not grant arbitrary Scheme/CInfScheme values linear structure. Declaration/profile and forged-view tests reject unsupported authority. `accepted_profiles`, `space_object` and public declaration/origin theorems connect the actual accepted environment. Publish this adopted-interface mapping rather than claiming the provisional namespace has shipped. |
| 2. General 2×3 value, distinct from ambient space/rank-one factors | **Covered.** The actual real example stores `[[1,2,3],[4,5,6]]` independently of the three nominal endpoint declarations and computes the full product. Its leading 2×2 minor is −3, so the ideal matrix is not rank one. The complex example's leading minor is 1. This is a concrete mathematical witness, not a claim that a new rank-factorization theorem was implemented. Native N tests execute both complete arrays; G checks ordered tensor views without a decomposability restriction. |
| 3. Composition/contraction with explicit dual roles and no implicit conjugation | **Covered.** N composition uses exact source/target bases; D algebraic evaluation and G edges use actual corresponding dual origins. ## #69 — finite networks within the broader tensor-network issue

The implementation admits connected trees with 2–64 occurrences, rank-two/three inputs and intermediates, at most one original rank-three occurrence, rank-two/three ordered output, and at most 1,024 explicit plan events. It supports branching/multiple independent intermediate producers, not only a two-map chain. Caller order, regrouping, scratch, destinations and permission changes are explicit. This is a substantive finite profile, **not completion of the literal general-rank parent issue**.

| Initial condition | Disposition and concrete evidence |
| --- | --- |
| 1. Ports/occurrences/edges/boundaries and structural nodes | **Finite core covered; broader structural nodes are parent residual.** G checks actual nominal axis roles, distinct occurrences, each port exactly once, actual connecting edges and ordered boundary. Copy/hyperedge/self-trace/metric insertion are not admitted nodes. The checker rejects them instead of silently supplying authority. Hermitian evaluation exists as an explicit separate D/M operation, not an invented generic network node. |
| 2. Composition, algebraic evaluation, explicit Hermitian example, higher rank | **Initial finite examples covered.** N/D execute map composition, covector evaluation and explicit conjugation/form-based pairing. G executes actual rank-three multi-edge trees with explicit intermediate packing/rebinding. General arbitrary-rank networks remain parent residual. It would be inaccurate to check off that entire unqualified parent sentence. |
| 3. Invalid roles/endpoints/conjugate/copy/hyperedge/trace/duplicate ports | **Covered rejection behavior.** G source and raw-wire tests reject wrong dual parents, same-sized foreign bases, duplicate/missing ports, unsupported plan actions and invalid graph structure. A disconnected cycle beside a valid boundary component is rejected through reconstructed producer coverage, not just counts. |
| 4. Nonconjugating complex result under contraction-order optimization | **Covered for the submitted deterministic order; optimizer/rewrite claim is parent residual.** G checks exact written left/right operands and plan order; explicit complex native oracles reject misplaced transpose/conjugation and flat-copy regrouping. There is no optimizer selecting a different order, and no claimed floating-point equivalence of parenthesizations. `exact_submitted_order` and `actual_contraction` are the applicable initial guarantee. |
| 5. Repeated immutable values with fresh occurrence ports, no factor aliasing | **Covered.** `immutable_repeated_occurrences_and_empty_rank_two_trees_are_supported` and the balanced two-producer/repeated-input fixture accept reuse. All component producers remain tied to the actual allocation/version/layout; a same-shaped replacement or overwritten producer rejects. Actual storage loans, not factor identities, gate writes. |
| 6. Independent IR validation and useful mathematical diagnostics | **Covered.** Strict public wire, independent name/profile/basis resolution and actual event replay reject forged graph/producers and unknown metadata. `public_tree_origin`, `actual_tree_lowering`, per-step acceptance, graph connectivity and ordered-boundary theorems retain the real checker's result. Both branch arms and all-body probes retain their own receipts. |

No arbitrary rank, cyclic contraction, trace/copy/category law or order-search implementation is added to the historical gate by this mapping. Keep #69 open for those explicit broader objectives, and record the finite subset rather than claiming its entire checklist is complete.

## Concrete remaining historical acceptance gates

The combined R/U implementation gate has passed on the exact integrated head recorded above. This map supplies the initial-profile evidence; keep its source/test/theorem links and issue dispositions synchronized as later changes merge. Neither publication nor a stale historical checklist is a substitute for the remaining gates.

An interval crossing the budget is inconclusive. The user currently has no dedicated controlled Linux host; this is an unavailable required facility, not a waiver or permission to relabel hosted CI.
